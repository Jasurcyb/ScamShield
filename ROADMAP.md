# ScamShield — дорожная карта для President Tech Award

## Цель

Создать безопасный Telegram MVP, который помогает пользователям Узбекистана
проверять подозрительные сообщения, ссылки, изображения, чеки и файлы на
признаки мошенничества. Основной трек — Incubation Program.

## Целевой MVP

Пользователь отправляет боту текст, URL, изображение или файл и за короткое
время получает понятный вердикт: «безопасно», «нужна осторожность» или
«опасно», причины и безопасные дальнейшие действия. Интерфейс доступен на
русском, узбекском и английском языках.

## Этапы

### 1. Фундамент: безопасность и качество (22–26 июля)

- [x] Ограничить размер и тип загружаемых файлов; проверять их содержимое.
- [x] Добавить защиту от перегрузки API, таймауты и безопасные ошибки.
- [x] Закрыть небезопасный CORS и исключить отправку лишних данных внешним AI.
- [x] Исправить маршрутизацию AI-провайдеров и единообразную обработку ошибок.
- [x] Зафиксировать зависимости, настроить тесты без реальных платных API.

**Критерий готовности:** API не принимает неограниченные файлы, не раскрывает
внутренние ошибки, тесты воспроизводимы локально и не требуют API-ключей.

### 2. Telegram MVP (27 июля – 2 августа)

- [x] Подключить Telegram-бота и безопасно хранить токен в окружении.
- [x] Реализовать команды `/start`, `/help`, `/language` и обработку сообщений.
- [x] Принимать текст, ссылки, изображения и файлы в допустимых форматах.
- [x] Показать пользователю прогресс, вердикт, причины и рекомендации.
- [x] Добавить русский, узбекский и английский тексты.

**Критерий готовности:** новый пользователь может выполнить полную проверку в
Telegram без обращения к техническим API или документации.

### 3. Точность и доказательства (3–6 августа)

- [ ] Собрать обезличенный набор тестовых кейсов: фишинг, безопасные сообщения,
  поддельные чеки и подозрительные вложения.
- [ ] Настроить пороги риска, снизить ложные срабатывания и добавить регрессионные тесты.
- [ ] Замерить скорость ответа, долю успешных проверок и точность на тестовом наборе.
- [ ] Зафиксировать ограничения продукта: это помощник, а не юридическое или банковское решение.

**Критерий готовности:** есть таблица метрик и демонстрационные сценарии,
которые можно показать жюри.

### 4. Конкурсная подача (7–9 августа)

- [ ] Описать проблему, аудиторию, решение, рынок, конкурентное преимущество и KPI.
- [ ] Подготовить скриншоты, короткое видео-демо и архитектурную схему.
- [ ] Проверить заявку на соответствие Incubation Track: команда 2–5 человек,
  все участники 18+, чётко сформулированные проблема и решение.
- [ ] Провести финальный security/code review и репетицию демо.

**Критерий готовности:** заявка, видео и демонстрационный сценарий готовы до
10 августа 2026 года.

## KPI для инкубационной программы

1. Время ответа: до 10 секунд для текста и до 30 секунд для изображений/файлов.
2. Не менее 30 проверенных демонстрационных сценариев без критических сбоев.
3. Измеряемая точность и доля ложных срабатываний на собственном тестовом наборе.
4. Первые тестовые пользователи и качественная обратная связь по понятности вердиктов.

## Принципы безопасности

- Не сохранять пользовательские файлы дольше времени анализа без явного согласия.
- Не показывать пользователям секреты, внутренние пути и ответы поставщиков AI.
- Не считать техническую ошибку доказательством безопасности файла.
- Объяснять, почему результат получен, и предлагать безопасное действие.
